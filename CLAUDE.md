# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

HouseAffairs (working name): an Android family household app (budgets, kitchen/pantry, medicines, plans, documents) shared across a household with per-member privacy. Kotlin, Jetpack Compose, Material 3, Hilt, Firebase Auth (Google only) and Cloud Firestore (offline-first), DataStore, WorkManager. Single Gradle module `:app`, package `com.houseaffairs.app`.

Product intent lives in `docs/PRODUCT_SPEC.md`. The behaviour rules actually implemented (Home ranking, budget/kitchen rules, rollover, location, digest, weekly review) are in `docs/ADD_AND_HOME.md`. Read the relevant section before changing a feature. The "Project layout" in README.md is out of date: the Add sheet lives in `feature/add`, and `feature/quickadd` holds only the parser.

/opt/homebrew/share/android-commandlinetools/emulator/emulator -avd HouseAffairs_Pixel

- The `local` build type sets `BuildConfig.USE_FIREBASE_EMULATORS = true`. `di/AppModule.kt` then points Auth (9099) and Firestore (8080) at `10.0.2.2`, and the sign-in screen offers test accounts (Asha, Ravi, Mia) instead of Google.

- `adb` is at `/opt/homebrew/share/android-commandlinetools/platform-tools/adb`.
- Optional `tmdb.apiKey=…` in `local.properties` enables movie lookups; TVMaze, Open Library and iTunes need no key.

## iOS and the shared module

- `:shared` is Kotlin Multiplatform (Android + iOS) and holds pure rules moved out of `app/` in the same packages, so Android imports didn't change. So far: `QuickAddParser` (with `ListTemplate`, `QuickAddDraft`) and `KindClassifier`, Attention, BudgetMath, Cards, Renewals, Repeats, Aisles, PrivateTopics, FirstAid, MediaSearch, `whatsAppNumber` (`core/util/Phone.kt`), the Home models (`HomeModels.kt`), Role/AppModule/Visibility (`Roles.kt`) and RolePolicy. No Firebase in it. Its tests (`shared/src/commonTest`, kotlin.test) run with `testLocalUnitTest`.
- Dates in shared code are `com.houseaffairs.app.core.time.LocalDate`: java.time.LocalDate on Android, kotlinx-datetime on iOS. Use the helpers in `core/time/Dates.kt` (`daysBetween`, `plusDays`, `isBefore`, `format("EEE d MMM")`…), never `java.time` or `LocalDate.now()`. Sort dates with `toEpochDay()`, since the shared type isn't `Comparable`. Amounts are `core/util/Decimal` (BigDecimal on Android; `decimalOf`, `compareValue`). Kotlin/Native rejects `,` in backticked test names.
- `:composeApp` is the iOS app's UI in Compose Multiplatform, with Firestore and Auth through GitLive's firebase-kotlin-sdk. It writes documents in the same shape as Android's `EntryRepository`.
- `iosApp/` is the Xcode shell: `cd iosApp && xcodegen` generates the project (Firebase iOS SDK comes from SPM). It needs `iosApp/iosApp/GoogleService-Info.plist` (git-ignored) for bundle id `com.houseaffairs.app` in Firebase project houseaffairs-98d6a.
- Google sign-in on iPhone: Swift (`GoogleSignInSwift` in `iOSApp.swift`, GoogleSignIn SDK from SPM) implements the Kotlin `GoogleSignInProvider` (`composeApp` iosMain) and returns the tokens; the shared `signInWithGoogle()` signs in to Firebase, so it's the same account as on Android. The URL scheme is `GOOGLE_REVERSED_CLIENT_ID` in `project.yml`, which must match REVERSED_CLIENT_ID in the plist. Creating or joining a home isn't on iPhone yet.
- Building for the simulator: use a specific simulator destination (`-destination 'id=…'` with `ARCHS=arm64`). A generic destination also asks for x86_64, which has no Kotlin target, and `syncComposeResourcesForIos` fails with "Cannot query the value of this provider". If `xcode-select` still points at the command-line tools, prefix commands with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`.

```bash
./gradlew :shared:iosSimulatorArm64Test           # shared tests on the iOS simulator (needs Xcode)
./gradlew :composeApp:compileKotlinIosSimulatorArm64
```

## Architecture

**Session and permissions.**
- `core/data/SessionManager` is the single source of truth: SignedOut, NeedsHousehold, or Ready(user, household, me). ViewModels read `session.state.value as? SessionState.Ready` to get the household id and uid.
- A `Member` has `moduleAccess` (money, stock, medicine, plans, vault). `ui/MainScaffold` hides tabs the member can't access, but enforcement is server-side in `firestore.rules`.

**Permission rules that must stay in sync.**
- `RolePolicy.defaultAccess` must match `defaultAccess()` in `firestore.rules`.
- Every household subcollection must be listed in `moduleOf()` in `firestore.rules`. Unknown collections are denied, so a new collection needs an entry there.
- Every document carries `createdBy` (fixed after create) and `visibleTo` (`["*"]` for everyone, or a list of uids).
- Rules aren't filters: list queries must use `whereArrayContainsAny("visibleTo", listOf(Visibility.EVERYONE, uid))`. Combined with `orderBy`, they need a composite index in `firestore.indexes.json`.

**Data layer (`core/data`).**
- Repositories wrap Firestore and expose `Flow`s via `observeSnapshots()` (`FirestoreFlows.kt`).
- Business rules are pure Kotlin functions in separate files, unit-tested with fixed dates: `BudgetMath`, `Envelopes`, `PantryMath`, `Attention`, `Digest`, `Trips`, `Cards`, `Geo`, `RightNow`, `LiveWell` and others. Put new money, kitchen or ranking logic in a pure function next to these and test it, rather than in a ViewModel or composable. Pass `today: LocalDate` in instead of calling `LocalDate.now()` inside the function.
- Money is `Long` minor units plus a currency code (`core/util/Money.kt`).
- Rollover and savings are never stored: `envelopes()` recomputes them from transactions and transfers since the budget's `startedOn`. Backdated expenses therefore correct past months automatically. Each month uses its own amount (`Budget.limitFor`, from `limitHistory` on the budget doc), so a raise applies from this or next month unless the person chooses "to every month" to fix a mistake. Planned spends count in the month they're dated for.

**Adding things: one parser, one form engine.**
- `feature/quickadd/QuickAddParser` turns a typed or spoken line into a `QuickAddDraft`.
  - `parse()` tries questions (`Ask`), then edits to saved entries (`Change`), then batches, then `parseSingle`.
  - `parseSingle` is an ordered chain of `parseX ?: …`. Order matters, and `parseTask` is the catch-all: anything unrecognised becomes a task. Add new patterns before it and add cases to `QuickAddParserTest`.
  - Questions answered on the spot (pure builders in `QuickAnswers.kt`, fed by Home's data in `AddViewModel.homeData`): `HAVE` ("do we have eggs?": amount, use by, where kept, on the buy list), `WHEN` ("when is Riya's birthday?"), `AGENDA` ("what's due this week?", "show my tasks"), `TO_BUY` ("anything to buy?") and `INCOME` ("got salary", "received 2000 from mom": not spending).
  - Other everyday lines: expenses keep the day said (`Expense.date`: "yesterday", "last night"), a brand is the shop wherever it's said, a pharmacy bill is Health, "lent/borrowed X" is a task to get or return it, "transferred X to savings" is a Fund, bare times 1 to 6 o'clock are pm, `extractDate` knows "this/next weekend", "next week/month", "in N days", "day after tomorrow". "Trip to Goa from 20 Dec" and "weekend at Coorg" are trips; "goal: …" is a weekly `Goal`; "watch/read/listen to X" and "gift for Riya: X" are list items; "good dosa at X" / "try X for Y" is a `Place`; "keys in the drawer" is where it's kept. A symptom said plainly ("headache since morning", "kid fell and cut his knee") is a symptom question; short words with other meanings (`AMBIGUOUS_SYMPTOMS`: gas, cold…) need more context.
  - Requests aimed at someone ("Rohan, please…", "remind Mom to…") are `parsePersonTask`, which sets `Task.forName`; `AddViewModel` gives it to the family member of that name, or keeps it as "Mom: …" for someone outside the app. "How much did we spend on X this month" is `Question.SPENT` (pure `spentOn`/`periodDays` in `SpentAnswer.kt`); "share my live location with Ravi" is `Question.SHARE_LOCATION`, which opens that person's WhatsApp chat (number picked once, kept per phone in `SettingsRepository.numberFor`), since no app can start WhatsApp's live sharing itself.
- `feature/add/EntryType` defines every addable kind as a schema: its collection, the module that guards it, and a list of `FieldSpec`s. Forms are generated from these, so a new kind or field is a schema change, not a new screen.
- `AddViewModel` maps each draft onto an `EntryType` plus prefilled form values. `EntryRepository` writes the entry, along with side effects such as an expense for a grocery that has a cost.
- **Unsure lines** (`QuickAddParser.isUnsure`: fell through to Task with no date, no "remind me", no doing-word) get a second opinion, in this order:
  1. what the family taught (`PhraseRepository`, `households/{hid}/phrases/{phraseKey}`, shared by all members and with its own rule in `firestore.rules`);
  2. the on-phone `KindClassifier` (naive Bayes on `SEED_EXAMPLES` plus the taught phrases);
  3. the `Assistant` interface, if Settings → Smart understanding is on (or the person taps "Ask Gemini").
- The `Assistant` also has `pick` (ranks real items such as dishes or the watch list and gives a reason; titles not in the options are dropped) and `coach` (the daily live-well nudge). Home uses them when Settings → Smart suggestions is on. What gets sent is built by the pure `pickInputs`/`coachSummary` in `feature/home/SmartPicks.kt`: titles and scores only, never amounts.
- `GeminiAssistant` (bound in `di/AssistantModule`) calls Gemini through Firebase AI Logic. `assistPrompt`/`draftFromAi` are pure and tested, and every field of the reply is validated. It only works against a real Firebase project with AI Logic enabled; in the `local` build every call fails and the app falls back silently. Correcting the kind on the suggestion card, or saving a guess, teaches the phrase.

**Undo instead of confirm dialogs.**
- Actions return a `SavedEntry(message, undo)`, usually built from a repository function that returns an undo lambda.
- Screens pass it to `onSaved`, and `MainScaffold.showUndo` shows the snackbar.
- Home reaches these callbacks through `LocalHomeNav` (`nav.saved`, `nav.edit`, `nav.open("plans/TASKS")`). A route of the form `tab/SUBTAB` opens a tab on a specific sub-tab.

**Home (`feature/home`).**
- Sections are `HomeSection` values. Each person's order and on/off switches are saved per device as a string (`parseLayout` / `encodeLayout`). When renaming or removing a section, add the old name to `RENAMED` so saved layouts migrate.
- "Today" is built by `buildToday()` (in `Attention.kt`) from `buildAttention()` plus open tasks. "Coming up" excludes whatever Today already shows.

**Long lists.** Pantry, Shopping, Medicines, Supplies and Where it's kept all use one component:
- `organize()` (`core/data/ListOrganizer.kt`, pure and tested) decides search, filter chips, "Needs a look", and which category groups are open.
- `core/ui/OrganizedList.kt` draws it. A list tab is one `itemList(...)` call, which lays out the Add button, the search box (chips past `LONG_LIST`), "Needs a look", sticky collapsible groups and the footer in the same order everywhere. Rows are the one-line `CompactRow`.
- Group emoji and colours come from `categoryStyle()`. Add a style there when adding a category. Kitchen lists use the stock accent and Things lists the vault accent.
- Groups a person opened or closed are saved per phone in `SettingsRepository.toggledGroups`.
- New item lists should reuse this, not hand-roll groups.

**Where things are kept.** Every physical item can have a place:
- Where it's kept entries (`keptAt` collection, `location` field; documents are the "Documents" kind and fill the Documents tab).
- Pantry, medicines and supplies use a `keptAt` field on the stock document, read into `PantryStock.keptAt`.
- "X is in Y" for an item already in pantry, supplies or medicines updates that item's place (`AddViewModel.placeExisting` → `EntryRepository.setPlace`). Anything else becomes a new Where it's kept entry.
- "Where is X?" searches all of them through the pure `whereIs()` in `ThingsRepository.kt`. Valuables are Vault-only, so kids get answers only from lists their role can see.

**Rules that span several files.**
- **Subscription prices:** `priceHistory` on the `recurring` doc (pure `priceOn()`/`changePrice()` in `SubscriptionPrice.kt`) keeps what earlier renewals cost. Changing a saved subscription's amount asks "New price applies" (`PriceFrom`: from the next payment, from a date, or every payment, which also corrects logged ones; `MoneyRepository.changeSubscriptionPrice`). Those form keys (`FORM_ONLY_KEYS`) are never stored. Logging, dues and Home's renewal amount use the price for that date. The form lists past payments (`MoneyRepository.pastRenewals`, by `fromSubscription`), each opening its expense to fix just that one.
- **Subscriptions:** a renewal becomes spending only once it's logged. `lastLogged` on the `recurring` doc records the latest one, and `Renewals.kt` works out what's owed. "Log it" in Today, or `onRenew = "Log it automatically"`, calls `MoneyRepository.logRenewal`, which uses a transaction for automatic logging.
- **Giving a task to someone:** saving a task for someone else sets `ask = "PENDING"` (`EntryRepository.save`; on edit, only when the assignee changes). They answer with `HomeRepository.answerTask`: yes → `ACCEPTED`; "can't do it" → `DECLINED` with `declinedBy`/`declineNote`, and `assignee` goes back to `assignedBy`. The giver then picks "I'll do it" (`keepTask`) or reassigns, which asks again. Rota turns are never asked. Who sees what is the pure `handoffOf()` / `handoffLine()` in `:shared` `Handoff.kt`; the buttons are `core/ui/TaskHandoff.kt`. No push notification yet: they see it next time they open the app.
- **Medicine courses:** a medicine with "How often" (`frequency`), `doseTimes`, `perDose` and `until` is a `MedicineCourse` (`:shared` `Medicines.kt`, read by `courseOf` in `HomeRepository.kt`). The count runs down from `countedAt` (set when the amount is edited), else when bought, skipping `skipped` days. `doseReminders()` rings for the people it's for, with "Taken ✓" / "Skip today" (`DoseActionReceiver`); `refillReminders()` warns two mornings before it runs out; `needsRefill()` drives the Today alert. "Won't take crocin today" parses to `SkipDose`. The row shows `scheduleLine()`.
- **Used up:** something with "Remind to restock" set goes straight back on the buy list (with "Don't buy again"); anything else asks "Add it to the buy list?" (`buyAgainFollowUp`).
- **Kids and money:** `Member.canAdd(type)` lets anyone add an expense; `ownExpense()` in `firestore.rules` lets them create and read only their own. Without Money access the Money tab is `MySpendsScreen` (own list, no totals).
- **Waste:** "Threw it away…" asks how much (`WasteDialog`); part of a pack lowers its level and appends to the stock doc's `wasteLog`, which `observeHistory` reads as waste for that day. Expired rows show a "🗑️ Bin it" button (`CompactRow.quick`). The pantry action is "Used up", not "Finished".
- **Trip plans:** trips (one kind for trips and outings) have `stops` (day, title, time, `about`, `photo`, `note` = what to do), edited on the trip card (`TripPlan` in `TripsCard.kt`). Adding a place looks it up on Wikipedia (`lookUpPlace`/pure `placeInfoFrom` in `PlaceLookup.kt`: a two-sentence summary and a photo from the top three matches); photos load with the app's User-Agent because Wikimedia refuses Coil's default. Tapping a place opens it in Maps, narrowed to the trip (`routeUrl(stops, area)`). A new trip's "Places, in order" line is day one until edited.
- **Trip money:** the card shows spent against the budget (pure `tripBudget()` in `Trips.kt`: nearing from 80%, over allowed and shown in red) and one-tap `TRIP_SPENDS` buttons (Tickets, Stay, Getting around, Food, Cafés, Shopping, Activities, Other) that open an expense already filed under the trip and that category. Saving an expense into a trip adds `tripSavedNote()` to the Undo message ("Goa is nearing its budget: ₹3,000 left").
- **Repeating tasks:** ticking one off (`HomeRepository.completeTask`) creates the next, with the due date and rota from `Repeats.kt` (`REPEAT_CHOICES`, `repeatDays()`: "Every 3 days", "Every 2 weeks"…).
- **Family chores:** Plans → Tasks → "🧹 Family chores" (`ChoresSheet` in `TaskViews.kt`) sets up shared chores: tasks with `source = "chore"` (`TaskItem.chore`), no assignee, a repeat, one-tap `CHORE_IDEAS` (`Chores.kt`). A done chore is next due its interval after the day it was done, not after its old due date. The pure `choreNudges()` rings a few at a time (late first, then a day-seeded shuffle) at the time it's usually done (`usualMinute`, else 10:00), plus an evening nudge when it's late or today's time has passed undone; "Done ✓ / Later today / Tomorrow" go through `HabitActionReceiver` (keys `chore:`). Separately, tasks ticked off three or more times with no repeat are learned as habits (`usualTasks`/`habitReminders` in `Habits.kt`).
- **Month and year views (one pattern everywhere):** `core/ui/MonthYear.kt` holds the pieces: `MonthCard` (this month at the top of a list, "This year ›"), `YearSheet` / `YearSummaryCard` / `YearChips` and `MonthByMonth` (each month folded into one line, the newest open). Use them for any new month/year view.
  - Kitchen, Medicines and Supplies: `StockMonthCard` / `StockYearSheet` (`UsageSheet.kt`), from the pure `kitchenMonths()` / `stockYears()` in `Usage.kt`, fed by `PantryRepository.observeHistory(kind)`. Grocery spend is compared with last month and the Groceries budget; waste is valued as cost × % left.
  - Money has three tabs: Month, Year and Savings. Expenses aren't a tab: each period's searchable list (`ExpensesSearch`, given the period) sits at the bottom of Month and Year, so month picking and categories aren't repeated.
  - Month: a "‹ October ›" switcher only once there's an earlier month, `BudgetHero`, planned & upcoming, "Where the money went" (`MonthOverviewCard` for that month), and expenses.
  - Year: from the pure `moneyYears()` in `MonthOverview.kt`; "Where the money is going" is `PaceChart` over the year (pure `yearPace()`/`yearLine()` in `SpendChart.kt`: spent month by month against the year's target, red above it, pacing from the month the budget started), with chips for All or one category against its own limit; then `CategoryBars` (each category against limit × months, pure `categoryBars()`), and the year's expenses (`yearPeriod()`). Amounts in these lines are whole currency units.
  - Plans: `PlansMonthCard` / `PlansYearSheet` (`PlansYear.kt`) on Tasks, Goals and Lists, from the pure `planMonths()` / `planYears()` in `PeriodReview.kt`.
- **Scan to fill:** the 📷 button on Expense, Grocery, Medicine, Supplies, Credit and Recipe forms reads text on the phone (ML Kit via Play services, `core/ui/ScanButton.kt`) and `AddViewModel.applyScan` fills fields from the pure `scanReceipt` / `scanExpiry` / `scanNutrition` in `Scan.kt`.
- **Health Connect** (`core/health`): read-only steps, sleep and workouts, connected per person in Settings. `WeeklyRepository.load` adds them to `WeekData`; `liveWell` then shows Steps (aim `STEPS_A_DAY`) and Sleep (`sleepScore`) and counts steps as walking. The client is pinned at 1.1.0-alpha11 because later versions need compileSdk 36 and AGP 8.9.
- **Photos gallery:** `core/photo/GallerySheet.kt` gathers every entry's `photos` (pure `galleryGroups` in `Gallery.kt`), opened from Things and the vision board.
- **Coming back daily:** Home marks the day opened (`SettingsRepository.markOpened`, per phone) and the hero shows the streak from the pure `streakOf`/`streakLine` (`Habit.kt`; cheers on `STREAK_MILESTONES`). The `FAMILY` section ("What's new at home") is the pure `familyFeed()` over `HomeData.recent`, others' things first, shown when the home has more than one member. At 8 pm `notify/StreakWorker` sends one nudge if a streak of two or more is at stake and the app wasn't opened today (pure `streakNudge`); it follows the digest's on/off switch and has its own channel.
- **Plain Home:** Home has one way to add, the Ask bar (plus the + on every tab). The Home filter chips moved into Customise. Bottom tabs always show their names.
- **Add options:** everything the sheet can add lives in `ADD_GROUPS` (`feature/add/AddOptions.kt`): forms (with presets, such as each list), plus typed options that fill the box (move money, questions). Each area is one sideways row. A new kind or list needs an entry there.
- **Add sheet:** one box to type, speak (mic) or scan a bill, its hint cycling through `examples`. Before anything is typed, `AddMenu` shows big tiles: kinds the person pinned (hold any kind; `SettingsRepository.pinnedKinds`, up to `MAX_PINNED`), then what they add most (`AddViewModel.usual` from the pure `usualKinds()` in `AddMenu.kt`, counts in `SettingsRepository.addedKinds`, `USUAL_DEFAULTS` on a new phone). Then "Several at once" examples (one typed line becomes a batch) and every other option once, one sideways row per area. Once something is typed, only the suggestion shows. New-entry forms have "Save + add another". Pins and counts use `AddOption.key` (`countKey()` counts a wish toward its list).
- **Tabs open at the top:** tab lists use `rememberTopListState(subTab)` (`ListControls.kt`), so coming back to a tab or switching its sub-tab starts at the heading.
- **Home nudges:** the `TIDY` section shows the pure `homeNudges()` (`feature/home/Nudges.kt`): stale things to clean up first, then empty corners to fill; "Not today" hides it till tomorrow.
- **Setup gate:** `SettingsRepository.setupDone` records that every permission was answered; until then `SetupGate` covers the app at launch, and the tour's Skip goes to the setup step instead of past it.
- **What was scanned:** the pure `scanKind()` (`Scan.kt`) tells a bill from a nutrition label or pack, so `applyScan`/`fromBill` refuse the wrong form with a plain note instead of filling junk. When the rules read a bill only partly and Smart understanding is on, `Assistant.readBill` asks Gemini (pure `billPrompt`/`billFromAi`, every field checked).
- **Notifications off:** Home shows `NotificationsOffCard` while the phone blocks the app's notifications, with "Turn on" to the system page; it rechecks on resume.
- **Lists tab:** with every list showing, each keeps its top `LIST_PEEK` (planned, then most ❤️) and a "See all N" that opens that list.
- **Scan a bill:** in the + sheet, `AddViewModel.fromBill` turns a bill (pure `scanBill` in `Scan.kt`) into a batch: the expense plus each item, to medicines for a pharmacy bill, else the pantry (no cost on items, so it isn't counted twice).
- **Category history:** tapping a category in Money's envelopes opens `CategorySheet` from the pure `categoryReport()` (totals, 12 months, by shop, every expense).
- **Tasks and recipes arranged:** Tasks open with a "Today" header (ring from the pure `dayProgress()` in `TaskViews.kt`, Mine/All), an add box that saves typed lines straight away (`PlansViewModel.quickAddTask`, through the parser, so "call mom at 5 pm tomorrow" keeps its date and time; ⋯ opens the full form), then `taskBuckets()` (waiting, overdue, today… no date; long ones fold) as rounded group cards (`TaskCardRow`). The circle finishes a task; its date chip opens the pure `rescheduleChoices()` (today, tomorrow, the weekend, next week, no date → `HomeRepository.moveTask`, with Undo). Done sits at the bottom.
- **Plans look the same on every tab:** `PlansHeader` (Tasks' today, Goals' this week with a ring, Events' next up), `AddRow` styled like Tasks' add box, and rows in `CardRow` group cards. Goals have a bar you slide or tap (`GoalRow`): it fills as the finger moves, names the step (`GOAL_STEPS`/`goalStep()` in `Goals.kt`) with a light buzz at each one, and saves on release with Undo (`ThingsRepository.setGoalProgress` returns it). Month cards sit at the top of Tasks, Goals and Lists. Month cards sit at the bottom. Recipes are a menu: `byMeal()` puts each dish under Breakfast, Lunch, Dinner, Snacks, Desserts, Drinks or Other (`RECIPE_MEALS`; "Lunch or dinner" sits in both, the coming meal from `mealAt(hour)` leads), drawn as a chip row plus two-across `RecipeTile`s with `MEAL_PEEK` per meal. All in `Arrange.kt`.
- **Home is short on purpose (about two screens):** Today's header has a ring of cleared/total; setup, the live-well nudge and tidy-up share one swipeable `WorthALook` row of equal-height cards; Coming up is a sideways strip of date cards; the cheer is one row when idea cards follow. Don't add full-width stacked cards to Home: put new extras in `WorthALook`.
- **Left to clear:** under the deck, everything else open for this person is always listed (`CLEAR_PEEK`, then "Show all"), each row one tap from cleared, with `clearedLine()`. With no to-dos left (idea cards don't count), `CheerCard` says "Hurray, nothing for you!" and the day's `cheerLine()` (`Moments.kt`). On the way, `MilestoneCard` cheers once each at `CLEAR_MILESTONES` (3, 5, 10… cleared today; pure `milestoneReached()`, shown ids kept in the handled set).
- **Home by time of day:** under the hero, Home is a swipeable deck built by the pure `momentCards()` (`Moments.kt`): `Moment.at(hour)` picks morning, afternoon, evening or night, and each leads with something different (things to do, lunch and errands, dinner, the spend question and winding down). Today's things are capped at `DAY_GOAL`; answered cards go into the per-phone handled set so the deck empties.
- **Category while typing:** on a new expense, typing "Where or who" sets the category and the field's icon (`AddViewModel.update` → pure `guessCategory` in `CategoryGuess.kt`): what the family filed that name under before (`learnedCategories` over their own expenses) wins over the parser's keywords (`QuickAddParser.categoryOfWord`). A category picked by hand is never overwritten.
- **Things people forget:** tasks ticked off again and again without a repeat ("Do laundry") come back in Today when they're due by the family's own rhythm (pure `usualTasks()` in `Habits.kt`, an `Attention` with `habit` set; "Add to my day" calls `HomeRepository.addTask`). They also ring as notifications on the due day at the time they're usually done (pure `habitReminders()`/`usualMinute()`, from `HomeData.done`, every ticked-off task with its time), with "Done ✓" (`HomeRepository.logDone`), "Later today" (`SNOOZE_MINUTES`) and "Tomorrow" (`Reminders.putOffTill`), handled by `HabitActionReceiver`. `likedBefore()` turns a well-rated saved place into the deck's eat-out card ("You loved it last time").
- **Surprises:** a gift idea's "For whom", or a trip's "Keep it a surprise from", narrows `visibleTo` to everyone else (`surpriseFor`/`hiddenFrom` in `Surprises.kt`, applied in `AddViewModel.persist`). People who join later don't see it either, since the list is fixed when saved.
- **One box to ask, add or find:** the + sheet ("Ask, add or find") also searches as you type: `AddViewModel.loadFinds()` reads what this person can see when the sheet opens, and "In your home" (`FoundAtHome`) lists the top `searchAll()` matches, above the suggestion when the line would only become a task. Each opens its form (`Findable.entryType()`).
- **Search results say what they are:** `Findable` carries amount, currency, the day that matters and the spending category (dates arrive as `LocalDate`, converted in `SearchRepository`); `Findable.line()` writes "₹640 · Dining · today", "Due tomorrow", "use by…", "📍 where". `searchAll(query, items, categoryOf)` also matches a word's spending category (the parser's `categoryOfWord`, plus `CATEGORY_WORDS`: "food" → Dining and Groceries). `SearchSheet` leads with `searchSummary()` (spent, how many, by category, what else turned up), kind chips to narrow, recent searches (`SettingsRepository.recentSearches`, pure `rememberSearch`, saved when a search leads somewhere), and `didYouMean()` (closest word within two letters, same start winning a tie) on a dead end.
- **Search:** the 🔍 in Home's hero opens `SearchSheet`. `SearchRepository.load` reads every collection the role can open once; the pure `searchAll()` (`SearchAll.kt`) matches names, any text on the entry, topics (`TOPICS`: "travel" finds passports, hotel bookings, the Travel list; each first-aid condition finds its medicines by `KNOWN_MEDICINES` names), one typo (`oneEditApart`), and people by name (uids in `forWhom`/`assignee`/`who` become first names), grouped by kind. A new collection needs a heading in `SEARCH_GROUPS` to be searchable.
- **Combined search:** `parseSearch()` (`SearchQuery.kt`) reads filters out of the line before matching words: `#tags`, dates ("today", "last month", "this week", "October 2025"), amounts ("over 500", "under 2k"), states ("expiring", "expired", "overdue", "due") and kinds (`KIND_WORDS`: "expenses", "tasks", "medicines"…). `SearchQuery.fits` applies them, and a filter-only line ("overdue tasks", "#goa") returns every match. The sheet shows what it understood as chips; `foundLine` reads it back.
- **Tags:** any "#word" typed in the + sheet is split off by `splitTags()` (`Tags.kt`) before parsing and saved as the entry's `tags`. Every `EntryType` gets an optional "Tags" field unless it has its own (Expense keeps its choice list).
- **Daily live-to-100 check-in:** on opening, `DiaryCatchUp` asks about days with no diary entry (pure `missedDays()` in `CatchUp.kt`): four answers (`DAY_QUESTIONS`: moved, ate well, people, slowed down; 0–2 each), a mood and an optional line, saved as `well` on the diary doc. The latest missed day can't be skipped or closed; older ones can. `WeekData.dayChecks` feeds the wheel (`dayScore`: "Moved each day", "Ate well", and Right tribe/Unwind before the weekly check-in). `checkInReminders()` rings at `CHECK_IN_MINUTE` each evening until today's is answered (`Reminders.markCheckedIn`).
- **Bin it** opens the waste choice first; every used-up or binned item's follow-up has "Put it back" (`PantryRepository.putBack`). Throwing away part of a pack (from a list or the month view) shows `wasteFollowUp()`: add to the buy list, or put it back (`wastePart` returns the undo: level, amount and the waste entry). Dose reminders ring for the people a medicine is for and whoever added it; choosing "How often" fills the times in.
- **Vision board:** Plans' vision board is a pinboard by default (`feature/plans/VisionBoard.kt`): hold a card to drag it (order saved for the family as `boardOrder` on each dream, pure `boardOrdered`/`moved`/`boardOrders` in `DreamBoard.kt`), tap to flip it for progress. "By when" shows the older rows by horizon. A dream's first photo fills its card.
- **Dreams in lists:** Travel, Car/Home/Gadget and Education dreams also show in the Travel, "To buy someday" and Study lists (`dreamsByList()` in `DreamLists.kt`). It's the same dream document, not a copy, so tapping it opens the vision board's `DreamSheet`. Money's "Coming up" routes rather than edits: planned spends go to This month's "Planned & upcoming", dreams to `plans/DREAM:<id>` (opens that dream), trips to the vision board.
- **Thrown away:** "Threw it away" sets `status = "WASTED"` and `wastedAt` (level kept, for valuing it); "Finished" sets `USED_UP`. Lists hide both via `GONE_STATUSES` (`:shared` `HomeModels.kt`), so use it rather than checking `USED_UP` alone.
- **My story:** the review screen has Week (the diary and wheel), Month and Year (`periodStory`, from the pure `periodReview()` in `PeriodReview.kt`, loaded by `WeeklyRepository.loadPeriod`).
- **Finished things are cleared after a year:** done tasks, list items and goals are deleted by `ThingsRepository.clearOldFinished` once `shouldClear()` (`Retention.kt`) says so, which is never before February after their year, so the yearly story stays whole. It runs once per app start. Goals stamp `doneAt`, list items `updatedAt`, tasks `completedAt`.
- **Restock:** predictions use ticked-off shopping items (`boughtAt`) plus groceries added as bought (`Restock.kt`, `PantryRepository.observeHistory`).
- **Private categories:** these live on the household doc (`privateTopics`: name → who may see). Besides the four sensitive topics, the owner can make any kitchen or supply category private (`privateChoices()`, in-use ones first), picking who it's hidden from (`seenByAllBut()`). `privateTopicOf(…, chosen)` matches them by category, and `AddViewModel.persist` narrows `visibleTo` for new entries on them.
- **Hidden costs:** `hideCostsFrom` on the household doc (owner-set, Settings → Privacy). For those people `CostPrivacy.hidden` (`core/ui/Costs.kt`, set in `MainScaffold`) turns amounts outside Money into "•••" through `shownMinor`/`shownCompact`, trips drop their budget bar, Home drops money, and the Money tab is `MySpendsScreen`. It hides the display only: the trip doc still holds its budget. Use `shownMinor` (not `formatMinor`) for any amount shown outside Money.
- **Settings is short on purpose:** Calendar, Health, Drive, Smart help and movie keys sit in one `ConnectedAppsSheet`; private categories and hidden costs in `PrivacySheet`. Put a new connection or privacy switch there, not on the page.
- **Symptoms:** "I have fever and cold" is one question for every condition said (pure `caresFor()` in `:shared` `FirstAid.kt`, joined with `SYMPTOM_JOIN`); `medicinesFor` matches the "Used for" tag or a common name (`KNOWN_MEDICINES`: Crocin, Dolo, Sinarest…), so untagged medicines are found too.
- **Teens and medicines:** teens only see medicines where they're in `forWhom`. This is enforced by `canUseItem` in `firestore.rules`, and every medicine query must use `RolePolicy.ownMedicinesOnly`.
- **Share sheet:** shared text and links arrive through `MainActivity` → `SharedInbox` → the Add sheet. Routing is in `Shared.kt`.
- **Google Calendar sync** (`core/calendar`):
  - It's per person, opt-in from Settings. It uses the `calendar.app.created` scope, so it can only see the "HouseAffairs" calendar it creates.
  - `planSync()` is the pure two-way rule set: the app wins when both sides changed; deleting in Google only stops syncing that item.
  - `CalendarSyncer` applies the plan. `CalendarStore` keeps the agreed state per phone, and `CalendarWorker` runs every 6 hours.
  - It needs a real Firebase/Google Cloud project with the Calendar API enabled and the scope on the OAuth consent screen. It can't run against the emulator's demo project.
- **Google Drive** (`core/drive`): `drive.file` scope only, so the app sees just what it made under "HouseAffairs". Backups go to HouseAffairs/Backups (`DriveRepository.backup`/`restore`; restore puts entries back, recreating deleted ones as the restorer since rules fix `createdBy`). Uploaded documents go to HouseAffairs/Documents/<type> and become `keptAt` entries with `docType`, `driveLink`, `driveFileId`. Pure parts in `core/data/DriveLayout.kt`. Needs the Drive API enabled in the Google Cloud project.
- **Your data** (Settings): "Download my data" (`HouseholdRepository.exportEntries` → pure `exportJson`/`expensesCsv` in `Export.kt`, shared through the FileProvider's `export/` path). "Delete my account" (`HouseholdRepository.eraseMe`, then `AuthRepository.deleteAccount`): private entries always go, shared ones only if asked; an owner hands over to `successorOf` (first adult who joined); the last member deletes the whole home (owner-only `delete` rules on the household and `phrases`). `DATA_COLLECTIONS` must match `moduleOf()`.
- **Family service keys:** OMDb and TMDB keys are set by the owner in Settings → Connected apps and stored on the household doc (`integrations`). `WatchRepository` uses them, falling back to `local.properties`.
- **Follow-ups:** after "bought", "watched" or "finished", a quick-options sheet appears (`FollowUps.show(...)`, hosted in `MainScaffold`). The builders are pure functions in `core/data/FollowUps.kt`.
- **Recipe fit:** `RecipeFit.missing` and `short` drive what's shown: "Missing: …" and "need more …", never "2 of 4". Ideas only list dishes you can cook, or ones that rescue expiring food. Every suggestion (ideas, "what can I cook", cravings, macros) comes only from the family's saved recipes; `SAMPLE_RECIPES` exists just to seed the demo home. Cooking is blocked when `CookPlan.enough` is false.
- **Demo mode:** "Try the demo" signs in anonymously, creates "Demo home" and seeds it (`DemoSeeder`). It needs Anonymous sign-in enabled in the Firebase project.
- **Optional keys** in `local.properties`: `tmdb.apiKey` and `omdb.apiKey` (IMDb and Rotten Tomatoes).

**Notifications.** `notify/DigestWorker` sends one daily digest via WorkManager. `HouseAffairsApp` reschedules it whenever the notification settings change. The digest content comes from the pure `Digest.kt`.
- Timed reminders ("call mom at 5:30") are separate: the pure `plannedReminders()` (`:shared` `Reminders.kt`) picks them from Home data, and `notify/Reminders` sets AlarmManager alarms. `HouseAffairsApp` re-plans whenever Home data changes; `ReminderWorker` every 4 hours and `ReminderBootReceiver` after a restart. A task's time is the `time` field ("5:30 pm").
- `POST_NOTIFICATIONS` is asked in the first-run tour (`ui/TourScreen`, steps from `core/data/Tour.kt`, progress in `SettingsRepository.tourStep`). The tour shows after first sign-in, after "Reset everything", and from Settings.

## Conventions

- UI strings are hard-coded English (not yet in `strings.xml`), written as short plain sentences.
- Comments explain *why* a rule exists, usually in one line. Keep that density.
- Dependency versions are pinned together in `gradle/libs.versions.toml`.
- `app/google-services.json` is git-ignored and per developer. The `local` build uses `app/src/local/google-services.json`.
